# 数学 計算ドリル（index.html）

**GPTの仕事は「問題データの書き換え」だけ。** 編集前に `index.html` の現在の全文を取得すること。

## 構造
`index.html` 1ファイル。編集してよいのは `<script id="problems" type="text/plain">` と `</script>` の**間だけ**。それ以外（style・body・UIロジック）は頼まれない限り1文字も変えない。
問題数・進捗・解答一覧・コピー用テキストはデータから自動生成される。

## 書式
問題は `---` で区切る。1行1項目「キー: 値」、値は1行で書く。LaTeXはそのまま書く（エスケープ不要）。

```
科目: 数学IA
単元: たすき掛け
難度: 2
問題: 次の式を因数分解せよ。
式: 6x^2+x-2
答: (2x-1)(3x+2)
解説: $6=2\times3,\ -2=-1\times2$ の組合せ。
---
```

- 必須: `科目` `単元` `問題` `答`。任意: `式` `解説` `難度`（1〜3）。
- `式` と `答` はLaTeXのみ（`$`で囲まない・日本語を入れない）。`問題` と `解説` の文中の短い数式だけ `$...$`。
- 答えが複数なら `\begin{gathered}A\\ B\end{gathered}`。
- `</script>` を書かない。行頭 `#` はコメント。
- 書式エラーは画面上部に赤字で出る。出たらその行を直す。

## 出題ルール
- 既定は20問（数学IA 10問 → 数学IIB 10問）。ユーザーの指定（単元・難度・数・科目）が最優先。
- **数字だけ変えた焼き直しは禁止。** 既存問題と重ならない単元を優先し、同じ単元なら問い方を変える。
- 6種類以上の問い方（求値／解く／因数分解／最大最小／定数を求める／一般項／個数・確率／角・長さ・面積 など）を混ぜ、隣り合う問題で単元・形式を変える。
- 難度は★1〜2中心、★3は最大2問。答えは整数・簡単な分数・簡単な根号になるようにする。
- 範囲: IAは式の計算・2次関数・三角比・場合の数と確率・整数・データ分析など、IIBは整式・複素数・図形と方程式・三角関数・指数対数・微積分・数列・ベクトル・統計的推測など。

## 手順
1. 現在の `index.html` を取得し、既存問題の単元・形式を確認
2. 問題データを書く
3. **答えを2回、別の方法で検算**（できない問題は出さない）
4. 問題データ部分だけ差し替えてコミット（日本語1行。例: `問題: 20問を入れ替え`）
5. 報告: 使った単元の一覧とコミット内容を簡潔に

## コミット前チェック
- [ ] 問題データ以外を変更していない
- [ ] 各問題に必須4項目があり、問題の間に `---` がある
- [ ] `式`・`答` に `$` と日本語がない
- [ ] 焼き直しになっていない／検算した
1. 元の問題を模倣しない

既存問題の数値だけを変えた問題を禁止する。

既存問題の数値や変数名を変更しただけで、解法・設問形式・論理構造が同じ問題を禁止する。

問題文を言い換えただけの実質的に同一な問題を禁止する。

既存問題の出題順や単元構成をそのまま踏襲することを避ける。

過去に生成した問題も既存問題として扱い、同じ問題の再生成を避ける。

2. 問題の構造から新しくする

新規問題では、可能な限り以下の要素を変更する。

問われる数学的概念や着眼点

解法のアプローチ

与えられる条件と求める対象の関係

設問の形式や問題の構成

計算過程で必要となる操作や思考

単に数値を変えるのではなく、同じ単元であっても異なる発想や解法が必要になる問題を優先する。

3. 既存問題との類似性を検査する

問題を確定する前に、既存問題および今回作成した他の問題と比較する。

以下のいずれかに該当する場合は、原則として不採用とし、問題の構造から作り直す。

数値や文字を置換すると既存問題になる。

問題文を言い換えただけで、求めるものと解法が実質的に同じ。

複数の問題が同じ出題パターンに偏っている。

既存問題と比べて、新しい問題としての独自性がほとんどない。

4. 多様性を優先する

問題数を埋めることよりも、問題ごとの独自性と多様性を優先する。同じ単元に偏らず、複数の解法や考え方を扱う。ただし、指定された学習範囲と難易度から逸脱してはならない。

5. 解答の正確性を維持する

独自性を高めるために、不自然な条件や複雑な計算を無理に導入してはならない。すべての問題について解答を実際に計算し、条件の整合性、解答の一意性、数学的正確性を確認する。
