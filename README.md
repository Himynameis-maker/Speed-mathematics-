# 数学 計算ドリル README（GPT用指示書）

## 0. 役割
- GPTの仕事は index.html 内の問題データの書き換えだけ。
- 作業前に index.html の現在の全文を必ず取得して読む。記憶や前回の内容は使わない。

## 1. 編集範囲
- index.html は1ファイル。
- 編集してよい場所は `<script id="problems" type="text/plain">` と `</script>` の間の行だけ。
- それ以外（head, style, body, UIロジック, README）は、ユーザーが明示的に頼まない限り1文字も変えない。
- 全文を出力する場合も、問題データ以外は元のまま完全に維持する。
- ファイル・ライブラリの追加は禁止。
- 問題数、進捗、解答一覧、コピー用テキストはデータから自動生成される。他の場所の修正は不要。

## 2. データ書式
- 問題と問題の間は `---` だけの行で区切る。
- 1行に1項目「キー: 値」。値は必ず1行で書く（改行しない）。
- LaTeXはそのまま書く。バックスラッシュのエスケープ、引用符、バッククォートは不要。

```
科目: 数学IA
単元: たすき掛け
難度: 2
問題: 次の式を因数分解せよ。
式: 6x^2+x-2
答: (2x-1)(3x+2)
解説: $6=2\times3,\ -2=-1\times2$ の組合せ。
---
```

- 必須キー: 科目 / 単元 / 問題 / 答
- 任意キー: 式 / 解説 / 難度
- 難度は必ず付ける（1〜3の整数）。解説は付けるなら全問に付ける。
- 式 と 答 はLaTeXのみ。`$` で囲まない。日本語を入れない（最大は `\max`、最小は `\min`、度は `^\circ`、dxは `\,dx`）。
- 問題 と 解説 は文章。文中の短い数式だけ `$...$` で囲む。長い式・分数・積分は 式 に入れる。
- 答えが複数ある場合は `\begin{gathered}A\\ B\end{gathered}` で縦に並べる。
- `</script>` を書かない。行頭が `#` の行はコメント。
- 書式エラーがあると画面上部に赤字でエラー行が出る。その行を直して再コミットする。
- 問題文はスマホ表示で2〜3行以内にする。

## 3. 問題数・配分
- 既定は20問。数学IA 10問、続けて数学IIB 10問の順。
- ユーザーが単元・難度・問題数・科目を指定した場合は、それを最優先する。
- 指定が曖昧でも質問せずに作り、使った単元を最後に報告する。

## 4. 出題ルール（多様性）
1. 同じ単元は1問まで。
2. 大分野ごとに最低1問は出す。
   - 数学IA: 式の計算 / 2次関数・方程式・不等式 / 図形と計量 / 場合の数と確率 / 整数の性質 / データの分析
   - 数学IIB: 整式・方程式 / 図形と方程式 / 三角関数 / 指数・対数 / 微分・積分 / 数列 / ベクトル / 統計的な推測
3. 問い方を6種類以上混ぜる（値を求める / 方程式・不等式を解く / 因数分解・展開 / 最大・最小 / 条件を満たす定数を求める / 式・一般項を求める / 個数・確率 / 角・長さ・面積）。
4. 隣り合う問題で、単元・問い方・解法を変える。
5. 答えの形を混ぜる。整数だけに偏らせず、根号・分数・負の数・複数の解・式・範囲を含める。
6. 難度は★1〜2中心。★3は最大2問。難度に起伏をつける。
7. 範囲を守る。数学III（変曲点、極限、置換積分など）は出さない。恒等式の係数比較は数学IIB。数学IAに入れない。

## 5. 独創性ルール（既存問題の模倣禁止）
「既存問題」とは、現在の index.html の問題、この会話で過去に出した問題、今回作る他の問題のすべて。
1. 数値・文字・変数名を置き換えただけの問題を作らない。
2. 数値を置き換えると既存問題になる問題は禁止。
3. 解法・設問形式・論理構造が同じ問題は禁止。
4. 問題文を言い換えただけの実質同一の問題は禁止。
5. 既存問題の出題順・単元構成を踏襲しない。
6. 新しい問題は、可能な限り次のいずれかを変える。
   - 問われる概念・着眼点
   - 解法のアプローチ
   - 与える条件と求める対象の関係
   - 設問の形式・構成
   - 計算で必要な操作
7. 同じ単元を使う場合も、別の発想・別の解法が必要な問題にする。
8. 問題数を埋めることより、独自性と多様性を優先する。不足するなら作り直す。
9. 独自性のために不自然な条件や過度に複雑な計算を入れない。学習範囲と難度を超えない。

## 6. 作成手順（この順で実行）
1. index.html を取得し、既存の全問題について「単元 / 問い方 / 解法」を書き出す。
2. 新しい20問の「単元 / 問い方 / 解法」の案を先に作る。
3. 案を、既存問題および案同士と比較する。次のどれかに当てはまれば、その問題を構造から作り直す。
   - 数値や文字を置換すると既存問題になる
   - 求めるものと解法が実質同じ
   - 同じ出題パターンが複数ある
   - 単元の重複、問い方・答えの形の偏りがある
4. 案を確定し、問題データを書く。
5. 全問題の答えを、2回別の方法で実際に計算して検算する。確認する項目: 条件の整合 / 答えの一意性 / 数学的正確性。検算できない問題は使わない。
6. 次のチェックリストを確認する。
7. 問題データ部分だけを差し替えてコミットする。コミットメッセージは日本語1行（例: `問題: 20問を入れ替え`）。
8. ユーザーへ報告する: 使った単元の一覧 / 問い方の内訳 / コミット内容。

## 7. コミット前チェックリスト
- [ ] 問題データ以外を変更していない
- [ ] 各問題に 科目・単元・問題・答・難度 があり、問題の間に `---` がある
- [ ] 式・答 に `$` と日本語がない
- [ ] `</script>` を書いていない
- [ ] 同じ単元が2問以上ない
- [ ] 大分野ごとに1問以上ある
- [ ] 問い方が6種類以上ある
- [ ] 答えに根号・分数・負の数・複数解・式が混ざっている
- [ ] 既存問題の数値違い・言い換えがない
- [ ] 数学IIIの内容が入っていない
- [ ] 全問検算した
